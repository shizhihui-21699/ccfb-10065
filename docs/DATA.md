# 数据构建与名次校准

本文说明 `data/generated/` 下的二进制数据是怎么来的，以及「名次」
（rank）为什么这样取值。名次是本项目的核心参数：它决定一个词典词
被判定为「攻击者第几次尝试就能猜中」。

## 1. 数据源

| 文件 | 内容 | 规模 | 来源 |
|---|---|---|---|
| `rockyou-withcount.txt` | 真实泄露口令 + 出现次数 | 1434 万行 / 1383 万唯一 | SecLists 镜像（rockyou 2009） |
| `zh_zipf.json` | 中文词频 `[词, zipf]` | 26.4 万词 | `wordfreq` 的中文混合语料（字幕/Twitter/维基） |
| `en_zipf.json` | 英文词频 `[词, zipf]` | 18.2 万词 | `wordfreq` 英文语料 |
| `names120w.txt` | 中文人名全组合 | 114 万 | Chinese-Names-Corpus（Apache-2.0） |
| `ancient_names.txt` | 古代人名 | 25 万 | 同上 |
| `chengyu.txt` | 成语 | 5 万 | 同上 |
| `pinyin_chars.json` | 单字拼音 | 4.2 万码位 | pypinyin |
| `pinyin_phrases.json` | 词组拼音 | 4.7 万词 | pypinyin |
| `zx_lists.json` | zxcvbn 六张频次表 | 9.4 万词 | zxcvbn 4.4.2 |

这些都是**公开语料**，`data/raw/` 不入库（体积大且可重新下载，
见 `tools/fetch_data.sh`）。`data/generated/` 只保留派生出的紧凑索引。

## 2. 为什么不用「词表位置」当名次

直觉做法是把词表按频次排序，第 N 位的名次就是 N。这在
26 万词的中文表上会严重失真：

- 「木星」在中文词表第 8.4 万位。若名次 = 8.4 万，等于说攻击者
  要枚举 8 万个中文词才轮到它——但真实的中文口令词表远没有这么大。
- 反过来，「中国」在第 3 位，名次 3，又低估了它在口令里的常见度
  （口令里更常见的是「woaini」这类，而不是政治词汇）。

位置把「词频的长尾」和「口令素材的常见度」混为一谈。正确做法是
用**概率**：zipf 得分 z 表示每 10^z 个 token 出现一次，即

```
p = 10^(z-9)
rank = C / p
```

C 把「自然语言语料里的词频」折算到「口令素材的枚举顺序」。

## 3. C 值的实测校准

中文没有公开口令语料，但可以用 rockyou 里**拼音形式**的口令反解 C。
这些拼音就是同一个词的 ASCII 写法：

| 词 | zipf | 拼音 | rockyou 名次 | 反解 C = rank·p |
|---|---|---|---|---|
| 宝贝 | 4.56 | baobei | 14 001 | 0.508 |
| 密码 | 4.65 | mima | 12 545 | 0.560 |
| 天使 | 4.61 | tianshi | 13 142 | 0.535 |

三者一致在 0.5 附近 → 取 **C_zh = 0.5**（取偏小值，即名次偏小＝
判定偏保守）。结果：

| 词 | zipf | 名次 |
|---|---|---|
| 中国 | 6.44 | 181 |
| 我爱你 | 4.50 | 15 811 |
| 密码 | 4.65 | 11 193 |
| 木星 | 3.42 | 190 094 |

英文用同样方法在 2 万个词上校准，C 的中位数是 **1.01** → 取 **C_en = 1.0**。

## 4. zxcvbn 的语义表：直接回归

zxcvbn 的六张表（common / wiki / names / tv 等）本身就是词表名次，
需要用 rockyou 做回归才能变成口令名次。取 `password_rank / list_pos`
的中位数：

| 表 | 中位倍数 | 用途 |
|---|---|---|
| passwords | 4.9 | 直接用 rockyou 重建，取 1.0 |
| english_wikipedia | 56.9 | 语义词表 |
| female_names | 25.1 | 姓名 |
| male_names | 20.1 | 姓名 |
| surnames | 73.3 | 姓名 |
| us_tv_and_film | 65.9 | 影视词 |

即语义表内部的名次普遍比口令名次「乐观」20~70 倍，必须放大。
姓名取三类中位数里偏保守的 22。

## 5. 姓名：「全组合枚举」的处理

姓名语料是 140 万条**全组合**（3815 个姓氏 × 数千个名字用字），
位置毫无频次含义，且「阿安」这类组合未必真有人用。

做法：
1. 按 `f(姓)·f(名用字)` 的边际概率排序（姓氏与用字频次是真实分布）；
2. 名次 = `NAME_C / 概率`，与中文词用同一套概率模型；
3. **只收录名次 ≤ 6 万（汉字）/ 4 万（拼音）的姓名**，避免全组合洪水
   把真实词挤出索引。

第 3 条是硬性约束：不做的话，73 万个姓名拼音会占满索引，「风铃」
（fengling）会以某个人名的身份被排到第 172 名——这是错误的。

拼音姓名还要额外乘 3.0 的惩罚系数（`PY_NAME_PENALTY`），并标记为
`zh_pinyin_name` 来源而非 `zh_pinyin`：同一个字符串如果也是真实词的
拼音，优先采用真实词的名次。

## 6. 分级与配额

最终索引约 1510 万唯一词，但只有两档写进运行时（合计 72 万条）：

- `dict1.bin`（12 万条，1.5 MB）——嵌入 WASM，首屏可用；
- `dict2.bin`（60 万条，7.8 MB）——按需 fetch。

按名次排序切档，但**给姓名类来源设配额**（tier1 最多 45%，tier2 最多
55%）。不设配额时 65 万条姓名会挤掉真实口令表，`pwned` 从 18.6 万条
缩到 2.8 万条，`anniversary` 这类常用词全部落榜。

当前各来源在 72 万条运行时索引里的占比（`zh_names` 与
`zh_pinyin_name` 是同一批姓名语料的汉字/拼音两种形态）：

```
zh_names        265 665    pwned          186 107
zh_pinyin_name  118 335    zh_words        82 556
zh_pinyin        26 969    en_common       23 147
en_names          9 582    en_zipf          6 954
en_tv               432    en_wiki            253
```

## 7. 已知局限

1. **中文名次模型没有口令级验证**。C=0.5 来自拼音锚点，锚点只有 3 个
   （其余拼音在 rockyou 里的名次过于靠后，噪声太大）。这属于
   明确假设，不是测量结果。
2. **rockyou 是 2009 年西方语料**，对中文、对 2010 年后的口令趋势
   （如游戏名、网红词）覆盖不足。
3. **极短口令**（`x`、`a`、`1`）的频次名次不可用：它们在 rockyou 里
   频次低，但攻击者会最先试。评估器对它们走字符集暴力估算，不走名次。

## 8. 复现

```bash
bash tools/fetch_data.sh      # 下载原始语料到 data/raw/
python3 tools/build_data.py   # 生成 data/generated/dict*.bin 等
python3 tools/build_breach_db.py
```

构建是确定性的：同频词按字典序二次排序，哈希冲突会直接报错退出。
