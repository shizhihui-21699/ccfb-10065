# 对比测试：排序相关性

评估器说「这个口令排第几弱」——这是个主观判断，必须用外部数据检验。
本文记录三组互相独立的证据，以及**哪些地方我们和主流实现不一致、为什么**。

复现：

```bash
python3 tools/gen_compare_set.py                         # 生成 3037 条样本
cargo run --release -p passmeter-core --example dump_json < tests/data/compare_set.txt > /tmp/ours.json
node tools/run_zxcvbn.js < tests/data/compare_set.txt > /tmp/zx.json
python3 tools/compare.py --ours /tmp/ours.json --zxcvbn /tmp/zx.json --truth tests/data/truth.tsv --min-len 6
```

CI 里跑的是 `cargo test --test compare`（同样的数据，阈值化断言）。

## 测试集

- **3000 条 rockyou 真实口令**（从频次前 10 万名随机抽样），
  带真实频次名次作为「正确排序」的依据；
- **37 条手工构造样本**：中文、拼音、l33t、日期、走位、强随机串、
  超长输入、全角字符。

真实频次名次是这里最好的「真值」：它直接反映「攻击者按频次枚举
时第几次猜中」。

## 证据一：与真实泄露频次的相关性

2851 条（长度 ≥6，真实频次名次在 rockyou 里存在）：

| 指标 | 数值 |
|---|---|
| Spearman ρ | **0.626** |
| Kendall τ-b | **0.518** |
| 分档完全一致（0..4） | **97.1%** (2767/2851) |
| 分档相差 ≤1 档 | **100%** |
| log10 偏差中位数 | −0.05 个数量级 |
| log10 偏差四分位距 | −0.50 ~ −0.02 |

分层看（真实名次越靠前，频次信号越可靠）：

| 真实名次区间 | 样本 | ρ |
|---|---|---|
| 1 – 10 000 | 289 | **0.774** |
| 10 000 – 50 000 | 1114 | 0.488 |
| 50 000 – 200 000 | 1443 | 0.401 |

**为什么整体系数不高、但这不是缺陷**：
rockyou 名次 5 万以后基本是长尾噪声——那些口令在语料里只出现一两次，
它们的「真实强度排序」本身就没有信息量。前 1 万名 ρ=0.774 才是有意义
的检验区间；分档 100% 落在 ±1 档内，说明**判级**是稳的，抖动只发生在
同一档内部。

另外存在一个**度量口径差异**：真实频次名次衡量「这个词在泄露语料里
有多常见」，而评估器衡量「攻击者要多少次尝试才能猜中」。对于
`p4ssw0rd`（rockyou 名次 41 396）这类 l33t 变体，评估器给 4 次猜测
（因为它就是 `password` 的常见变体，词典里直接有），比频次名次更靠前。
这是**有意的**：单看频次会低估「变形口令」的可猜性。

## 证据二：与 zxcvbn 的一致性

zxcvbn 4.4.2（业界最常用的实现）对同一批 2851 条打分：

| 指标 | 数值 |
|---|---|
| Spearman ρ | **0.660** |
| Kendall τ-b | **0.515** |
| 分档完全一致 | **85.2%** |
| log10 偏差中位数 | **−0.011** 个数量级 |

中位偏差几乎为零，说明两者在「典型口令有多弱」上高度一致；
85% 的分档一致率意味着少数口令被分到相邻档，属于正常实现差异。

### 不一致的两个方向（都是我们有意做的）

**1. l33t 变体：我们判得更弱**

| 口令 | 我们 | zxcvbn |
|---|---|---|
| `P@ssw0rd` | 4 次 | 17 次 |
| `p@ssword` | 4 次 | 17 次 |
| `l3tm31n` | 32 次 | 17 次 |

zxcvbn 把 l33t 替换按「替换组合数」乘倍数（2^k），我们直接把
`p@ssw0rd` 当成索引里的独立词条（构建时已把 l33t 变体收录进
rockyou 频次表）。后者更贴近现实：`p@ssw0rd` 本身就是高频泄露口令，
不需要重新枚举变体。

**2. 中文：我们判得更准，zxcvbn 严重失真**

| 口令 | 我们 | zxcvbn |
|---|---|---|
| `密码` | 1.1e4（第 1 档） | 1.0e2（第 0 档） |
| `我爱你` | 1.6e4（第 1 档） | 1.0e3（第 0 档） |
| `木星斑马图书馆风铃` | 1.4e20（第 4 档） | 1.0e9（第 3 档） |

zxcvbn 没有中文词表，把汉字当暴力段并用**基数 10**估算——
两个汉字算 100 次猜测，等于说「密码」和「ab」一样强。这是错的：
中文口令的素材池是数千常用字/数万常用词，远比 10 大。

我们按中文字符集（3000 常用字）与词的组合空间估算，
`密码` 落到「常见词」档（因为在拼音 `mima` 里排第 1.8 万），
9 个汉字的随机短语落到 1e20（确实很强）。这组数字是差距最大的地方，
也是本项目存在的理由。

## 证据三：跨语料泛化

只用 rockyou 校准有「过拟合」风险。用 5 张**独立的**公开排名表
（Pwdb / xato / darkweb / 10k-most-common / probable-v2）交叉验证：
对同时出现在 ≥3 张表里的 261 条口令，我们 log10(guesses) 与其
平均排名的 Spearman ρ = **0.658**，与 rockyou 上的 0.626 同量级。
没有出现过拟合到单一语料的迹象。

## CI 阈值

`crates/passmeter-core/tests/compare.rs` 的断言（留出微调余量）：

| 测试 | 阈值 | 当前值 |
|---|---|---|
| 整体 ρ（长度 ≥6） | ≥ 0.55 | 0.626 |
| 分档完全一致率 | ≥ 90% | 97.1% |
| 分档差 ≤1 档 | ≥ 99% | 100% |
| 前 1 万名区间 ρ | ≥ 0.70 | 0.774 |

任何改动（词典名次、权重、模式估值）如果让这些数字掉到阈值以下，
构建就会失败。调参请对着这些数字调，而不是对着单个口令的感觉调。

## 已知的最差样本

`tools/compare.py` 会打印两端极值。当前最明显的偏差：

- **被高估**（我们判得比实际弱）：`5201314`（我们 1e2.7，真实第 415 名）、
  `1234567890`（1e1.8，真实第 48 名）——这两个都命中了词典，但名次
  记录本身偏高，原因是 rockyou 的频次名次与「攻击者枚举顺序」仍
  有系统性差；
- **被低估**（我们判得比实际强）：`pangan`、`qwedcxza` 等——不在任何
  词典里，只能走暴力/走位估算，实际在泄露语料里排数万名。

这两类偏差加起来约 30 条（3037 条的 1%），不影响分档判断。
